# InsightGraph

[English](README.md) | 简体中文

> 把分散的信息组织成可探索的图谱，并从中提炼出可复用的「洞察」。

**状态：开发初期。** 产品尚未发布，本 README 介绍当前阶段的产品思想与使用方法；
工程文档见 [docs/](docs/README.md)。

## 产品思想

InsightGraph 的目标是：帮你看懂一个软件项目 —— 并且让你确信自己看懂的是真的。

把一个仓库交给它：它会读取代码，先构建出这个项目的结构地图（函数、类、模块、导入与调用关系），
再构建第二张地图，把技术概念与「项目具备的某种能力」连接回支撑它们的直接证据：
一个文件、一行代码、一处文档。最终你会得到一张可探索的地图 —— 项目做了什么，以及为什么可以相信。

- **看懂代码本来的样子。** 结构地图回答：*这个项目是如何组织和调用的？*
- **只相信有证据的结论。** 任何「项目具备某能力」的说法都必须能回指真实证据；没有直接证据的
  结论会被显式标记为推断 / 假设 / 无依据，绝不当作事实呈现。
- **可探索，而不是一问一答。** 洞察被组织成可导航的图谱：每个答案都与来源保持连接，
  一个结论会引出下一个问题。
- **结果可复现。** 同一个仓库、版本与配置，产生同样的分析过程，因此发现可以被复核、
  对比，并在此后反复查看。

## 使用方法（规划中）

```text
1. 把 InsightGraph 指向一个仓库（本地路径或远程 URL）
2. 它分析代码结构、收集文档与代码证据
3. 以交互式图谱浏览分析结果
4. 打开任意能力或结论，沿证据链回溯到源码 / 文档出处
5. 导出「每条关键结论都可回查」的研究报告
```
